# docs

## who you are writing for

the engineer woken at 03:20 by the noc. write plainly, say what to do,
get to the point. nothing is an emergency, because nothing is an
emergency. plain beats compelling: excitement makes documents worse.
stoic, no hype, no exclamation marks.

## how

- a substantial doc gets three passes: get it accurate, then put it in
  my voice, then make it clear. one wink at most, and cut it if it
  strains.
- you own prose you delegate. read it to this bar yourself; never hand
  on a subagent's draft as finished.

## what goes in a design doc

a design doc says how the thing works and why. nobody accepts anything
in a design doc. a limit you decided to live with is described as
behaviour ("a clock step over a second can run a task twice"), and the
decision itself goes in the commit or status note where it was made.

## facts

- a claim about state carries the date it was true and the reason. check
  it against the state on that date, not today's.
- run `date` before you write a time. never guess the clock.

## words

- prose under my name is lowercase; identifiers keep their case.
- "ultraviolet" is the charm library, written in full. "uv" is only
  astral's python tool.
- anything rendered for a person to read follows legibility/.
